## 顶层职责

| 项 | 职责 |
| --- | --- |
| SKILL.md | 12 个任务的路由表、上手主线、操作边界 |
| references/workflows/ | 每个任务一份流程：输入、步骤、停点、交付 |
| references/contracts/ | 证据、输出、质量、知识、图示与任务衔接约定 |
| references/adapters/ | 按真实入口适配：Web、服务端、原生/游戏、库与 CLI、数据任务、工程组织 |
| references/examples/ | 完整正反例，展示"能开始开发"与"信息分散无法定位"的差异 |
| scripts/ | 一个可选 inventory.py，只读目录索引 |
| assets/templates/ | 概览、架构、技术栈、地图、定位卡、库学习、机制等输出模板 |

一个完整 repo-pilot 目录包含所有任务资源，不另装子 Skill。仓库 site、tests、开发规范与企业项目资料不参与安装。

## 保存结构

默认只在会话展示；明确要求保存时写到目标 `.repopilot/`：

```text
<知识目录>/
├── 00-start-here.md        # 唯一入口、首屏、目录与来源
├── 01-architecture.md      # 架构四维与典型路径
├── 02-tech-stack.md        # 核心技术、版本、用途、证据
├── guides/                 # 开发规范与 libraries/
├── maps/                   # 独立地图
├── changes/                # 需求定位卡
├── traces/                 # 业务链路
├── mechanisms/             # 内部机制
├── appendices/             # 全量索引与原始证据
└── local/                  # 个人位置与练习，非共享
```

只创建需要的目录，不预先铺空结构。00 的来源区记录产物类型、Skill 版本、任务与目标、仓库标识、日期、源码状态、已读与排除范围。Skill 更新不会覆盖项目笔记。

## 图与案例

结构图与流程图沿用 logo 的深蓝描边、青蓝填色与地图导航风格；时序图用普通清晰技术风格。提示词写在 assets 中，安装版不需要根 logo。宿主无出图能力时保留 Mermaid 源码或文字树，不安装渲染服务。

## 扩展

新增框架只需补一份 adapter 的"按什么顺序读结构"，复用现有主线；新增任务要先明确输入、读取顺序、分支、产出与停点，再补按需资料。只有重复且确定的机械操作才增加脚本，不用文件数量证明工程化。

## 检查

```bash
node scripts/validate-skill-metadata.mjs
python -B -m unittest discover -s tests -p 'test_*.py' -v
```

Node 检查属于仓库维护工具，校验 frontmatter 并拦截仓库根出现游离 SKILL.md。可选脚本用 Python 3.10+ 标准库，Skill 本身不需要安装运行时。测试覆盖边界、预算、只读、完整复制与链接；真实项目与宿主端到端效果还需验收。
