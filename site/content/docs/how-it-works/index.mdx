理解这套机制，能解释掉 90% 的「装了没反应」。

## 三层按需加载

RepoPilot 的内容不是一次性全部进上下文的，而是分三层：

| 层级 | 内容 | 何时进入上下文 |
| --- | --- | --- |
| L1 | 技能入口文件的 frontmatter（`name` + `description`） | **常驻**，只占几十个 token |
| L2 | 技能正文（默认立场、工作流、边界） | L1 命中后才读 |
| L3 | `references/` 下的规则文件 | 正文里点名时才读 |

这就是为什么「项目地图协议」每次都会加载，而「上手路径」只在你要跑项目时才读——一个关于单个模块的问题，不该把整套上手指引也拉进来。

这层的调度规则写在 `manifest.yaml` 里：

```yaml
always_load:
  - references/project-map-protocol.md

references:
  on_demand:
    - condition: the user wants to run the project locally, or needs a step-by-step onboarding path
      path: references/onboarding-path.md
```

## 六步工作流

1. **建立项目地图** —— 读依赖清单、入口文件、目录树、构建配置。这一步不深入任何模块。
2. **识别架构分层** —— 技术栈、分层方式、构建部署、外部依赖边界，标注判据来源。
3. **确认当前目标** —— 没说清就先问。
4. **追踪业务链路** —— 从入口沿调用链走到数据落地。
5. **按需深入** —— 只展开目标相关模块。
6. **输出上手路径** —— 可执行动作，而非描述性结论。

## 为什么装了却不触发

按出现频率排序：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 完全没反应 | 会话是在安装**之前**启动的 | 开一个新会话 |
| 装了但从不激活 | 你的提问和 `description` 里的触发词不像 | 描述任务时带上「理清架构」「跑起来」「上手」这类词 |
| 找到了但读不到规则 | 只拷了单个入口文件 | 保留完整目录，重跑安装命令 |
| 装完过一阵失效 | 默认符号链接，CLI 缓存被清理 | 重跑命令并加 `--copy` |

最后一条值得单独说：**触发靠的是语义匹配，不是关键词硬匹配**。你要做的不是记住某个命令，而是像跟同事说话一样描述你要干什么——`description` 就是按这个思路写的。
