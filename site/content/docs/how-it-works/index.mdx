Agent 按 SKILL.md 执行，按目标读取当前 workflow 和 adapter。支持资料是内部操作手册；项目交付默认集中阅读，不必逐文件跳转。

## 技术预备，然后进入学习链路

首次分析项目或新模块，先静态列当前相关技术、三方库和共享包消费关系，询问哪些不熟悉；陌生项先做最小 Demo。用户都熟悉或明确跳过则直接进入下列流程。Demo 中的完整代码、数据流程、运行命令和结果在一份文档里，用户说“继续”后回到原分析位置。

项目根 `技术栈demo/README.md` 是“技术栈的使用”导航，每项 `<技术名>/README.md` 是完整示例；只在会话展示或指定目录优先。文档生成不会自动安装依赖或启动服务。

## 一条学习链路

1. **onboard**：识别用途、应用边界、模块、架构和核心技术。
2. **business**：用户做什么、模块怎么分工、典型动作怎样完成。
3. **trace**：每步输入从哪来，经过什么处理，输出交给谁。
4. **walkthrough**：要看代码时，每轮一个问题和一个小切片。
5. **locate**：需求先改哪里、照哪处同类实现、怎样验证。
6. **visualize**：需要图时，同页整合职责、完整场景和数据变化。

这些是选择路径，不强制每次走六步。明确的局部需求直接从对应任务开始，复用已读事实。library、deep、teach和refresh负责按需学习及维护；map、architecture、stack、standards提供对应专题。

## 集中呈现

默认会话中完整回答；要求保存时一份主文含内部目录。可视化默认一页显示当前场景全部步骤，关键数据和未知直接可见。导航用于快速定位，只有用户明确要钻取才隐藏到层级视图。

一个可视化页面按五个区块组织：案例与范围、完整时序图、分阶段数据案例、模块职责、来源与验证范围。

| 区块 | 回答的问题 |
| --- | --- |
| 案例与范围 | 这一次到底发生了什么，有哪些假设 |
| 完整时序图 | 谁传给谁，重定向有没有拆成两个半跳 |
| 分阶段数据案例 | 传了什么，每个字段从哪来 |
| 模块职责 | 谁负责什么（包含关系，不是执行顺序） |
| 来源与验证范围 | 哪些是模拟值，哪些还没核实 |

判断标准是不点任何按钮就能答出这五个问题。写法上的八条要求与常见退化，见[业务可视化](/docs/guide/visualize)。

## 小步但不中断

“继续”推进当前问题，“配置知道了、跳过”回业务，“返回”恢复实际阅读历史。Agent可以读完整函数核实，但无需把全部代码贴给新人。首次熟悉度确认只问当前相关技术；已有明确答复或沿原节点继续不重问，不要求答题。新陌生项可切 demo，学完恢复位置。

## 证据与工具

来源分静态确认、推断、未知和运行验证；模块注册不是执行顺序，候选接口匹配不证明部署连通。首次只静态检查；执行依实际授权。

可选inventory只列候选，缺Python用宿主搜索。单页业务地图模板不需构建依赖，也不请求目标服务。
