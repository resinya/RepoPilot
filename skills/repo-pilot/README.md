# `repo-pilot` 技能

[English](README_EN.md)

自动探索陌生代码仓库：先构建一张可导航的项目地图，再按你当下的目标，只深入真正需要的那部分代码。

## 适合用它做什么

- 刚接手一个仓库，需要知道从哪看起
- 需要把项目跑起来，但环境配置散落各处
- 想知道某个功能在哪实现、一条业务链路怎么走
- 要给新人写一份真正能照着做的上手指引

## 典型请求

- `这个仓库怎么跑起来`
- `帮我理清这个项目的架构`
- `新人怎么熟悉这份代码`
- `这条业务链路从哪里进、到哪里结束`
- `订单状态是在哪里变更的`

## 你需要提供

| 输入 | 必需 | 说明 |
| --- | --- | --- |
| 仓库路径或链接 | 是 | 本地路径最稳妥；链接时需要先能访问 |
| 你的目标 | 否 | 跑起来 / 改功能 / 排查问题 / 熟悉业务。不说明时会先问 |
| 关注范围 | 否 | 例如「只看支付相关模块」，可显著加快速度 |

## 产出

1. **项目地图** —— 带职责标注的目录树，标注依据为实际引用关系
2. **架构分层** —— 技术栈、分层方式、构建与部署方式、外部依赖边界
3. **业务链路** —— 从入口到数据落地的调用路径，带 `路径:行号` 锚点
4. **上手路径** —— 可执行动作序列，含 Windows / Linux 差异
5. **未覆盖清单** —— 明确列出本次没有读到的部分

## 边界

- 只负责让人理解仓库，不生成业务代码或重构方案
- 不对没有证据支撑的设计意图下结论，推测会明确标注为推测
- 不评价代码好坏、不做技术选型建议，除非你明确要求
- 仓库本身缺文档时如实说明「无依据」，不用通用最佳实践填充

## 工作方式

六步：建立项目地图 → 识别架构分层 → 确认当前目标 → 追踪业务链路 → 按需深入 → 输出上手路径。

同一个仓库，四个目标对应四条不同路径，所以**第三步一定会先确认你要做什么**。
