# Walkthrough：逐节点源码导览

## 输入、职责、产出

输入：应用/功能、真实入口、当前位置、视角和历史。每轮解释一个核心节点；默认会话，保存按[outputs](../contracts/outputs.md)。

## 步骤

1. **恢复位置**：读真实历史/笔记并复核文件，说明当前节点与上一节点关系。完成：位置不是猜测。
2. **读取节点**：声明、导入/注册、完整关键函数；大文件按符号补邻近条件。完成：核心输入输出和分支已读，截断部分补齐或标未读。
3. **解释职责**：为什么存在、输入谁给、输出谁消费、状态/副作用/关键约束，附位置。完成：描述支持当前目标，不逐行翻译全部源码。
4. **切视角**：结构/渲染、依赖、执行分别解释同一节点；返回看实际历史，看地图保留位置。完成：包装不当执行顺序，导入不当调用。
5. **交下一步**：给1～3个已确认候选和原因；自动模式一轮最多三个。完成：当前位置、已读、未知和继续方向明确。

框架入口可能显式启动、约定layout/page、bin、场景或任务注册，不统一找main.ts。Provider看初始化/作用域/消费者；服务端看注册/接口/注入；CLI看参数/调用/输出。

## 停点与例子

重复/循环、关键未知、外部源码不可见或偏离目标交断点。CLI从命令入口到format，下一节点可能测试或输出，不出现Router，见[CLI](../examples/cli-library.md)。展示不等于用户理解；需要练习转teach。

## 讲解要求

遇到框架样板文件（@Module、组件、CLI 入口）、配置文件或依赖注入模块，先按[讲解契约](../contracts/explanation.md)给最小骨架再叠业务，并分清框架默认与项目封装、枚举配置实际字段。涉及用户可能不熟悉的技术栈，先列出技术栈并询问，简报（白话概念→本项目用法→常用API→关系→流程图）后再讲本节点；简报到 library 深度转[library](library.md)。
