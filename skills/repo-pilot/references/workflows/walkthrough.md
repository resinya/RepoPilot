# Walkthrough：每轮一个问题，而不是一个大文件

## 输入与默认节奏

沿用应用、业务目标、当前位置和真实阅读历史。用户说“继续”推进当前问题的下一步；说“文件太大”立即把一个函数拆成若干小切片，不再把整个文件当节点。默认会话展示，保存才按[输出契约](../contracts/outputs.md)。

## 六步 SOP

1. **接上来路**：一句话说明上一步得到什么、现在要回答什么；重新核对文件与符号。
2. **读够证据**：Agent 读取完整相关函数、调用者、注册和必要分支；大文件按符号定位。为理解读取的范围可以大于展示范围。
3. **挑一个切片**：只呈现解决当前问题的代码，通常约 5～15 行，复杂表达式可先拆成语义等价的讲解写法，并明确不是项目原文或修改。行数是建议，不截掉影响结论的条件。
4. **先讲业务再讲语法**：谁给输入 → 当前步骤做什么 → 得到什么 → 谁消费。必要时解释参数别名、装饰器、回调或 Promise；不把全套语法教程塞进这一轮。
5. **标清进度**：给一条当前位置链，例如“用户提问 → 接收参数 → 确定会话”；同时说本段尚未做什么（若会影响理解）。登记模块不是运行模块，准备配置不是监听端口。
6. **明确下一步**：优先给一个下一符号与待解问题。可选一个白话理解问题，但用户“继续”无需先答题；自动模式按已授权节奏，最多三个节点。

首次分析新模块先完成/复用 [demo 前置确认](demo.md)，沿原节点继续不重新调查。涉及框架骨架、配置或陌生技术时按[讲解契约](../contracts/explanation.md)；配置已理解只给作用摘要。新出现且用户不会的核心技术可切 demo，保留当前问题与下一位置；不调查无关技术。

## 用户控制

| 用户表达 | 行为 |
| --- | --- |
| 继续 | 保持当前业务目标，推进一个已确认的小问题 |
| 配置知道了 / 跳过 | 记为用户要求跳过，不记为验证掌握；转下一业务节点 |
| 先讲业务 / 分模块 | 切 [business](business.md)，不继续展开启动配置或库 API |
| 返回 / 看地图 | 保留目标，回到实际上一步或给紧凑地图，不重新扫描全仓 |
| 想看某个包 | 当前应用/版本/消费者带入 library，讲清后可回原断点 |
| 放在一起 / 不要一直点 | 完整解释留在同一回复/主文，超链接作证据，不要求跳文件才读懂 |
| 做成图 | 按 [visualize](visualize.md)，默认单页集中呈现，导航只作辅助 |

## 停点与验收

重复、关键未知、外部实现缺失或偏离目标时交断点与下一证据。用户不用读完整大文件，就能说明当前几行的职责、输入输出及下一步。正反例见[业务学习](../examples/business-learning.md)。
