# Demo：技术熟悉度确认与最小实现

这是项目/模块分析的前置流程，也是同一 Skill 的 `demo` 任务。不另装子 Skill、不创建调度服务。完整项目用法属于 [library](library.md)，完整架构属于原任务。

## A. 先列当前需要的技术，再提问

1. **限定范围**：确认目标仓库、应用/模块及原任务；复用已有会话中的熟悉技术、明确跳过项与阅读位置。新会话无记录不能假定用户熟悉。
2. **轻量静态探测**：读清单、workspace成员、可得锁定版本、目标入口和少量 import/注册/调用上下文。按 [stack](stack.md) 分开声明与实际使用。只读当前模块直接依赖和理解主线所需的关键间接依赖；全项目按角色归组，不遍历锁文件所有传递依赖。排除生成的技术栈demo及已知自定义输出目录，不把教学包识别为业务应用。
3. **给可选择清单**：每行有技术/包名、白话用途、所属应用、声明/锁定版本、真实位置或未知。三方库和本地共享包分组；共享包给 `消费应用 → 包导出/封装 → 下游` 的已知关系，不把 import 当网络请求。引用位置只是预备地图，尚未交付完整架构。
4. **必须询问熟悉度**：使用宿主提问工具或一次简短提问，允许“都熟悉”“列出不熟悉项”“跳过 Demo”。同时告知默认保存位置。参考：

   > 这次涉及 React（页面）、状态库（共享状态）、RPC（跨进程请求）和本地共享包（封装）。上表哪些你还不熟悉？请列名称或编号，我会先在项目根目录 `技术栈demo/` 为每项生成一份完整最小示例文档，再回到订单模块分析。都熟悉或想直接分析，也可以说“跳过”；只在会话展示或改保存目录请一并说明。

   问题中的技术必须替换为本次实读发现，不能照抄例子。用户此前明确说“RPC 不会，先给 Demo”已经回答，无需再问。用户只问单个符号/字段、要求复核文档或继续原节点时不重新调查；新模块只补问新出现且影响理解的技术。
5. **等待实际答复**：熟悉/明确跳过则直接恢复原任务；陌生项进入 B。无答复只能继续核对清单/版本等独立静态事实，不能假设都懂、自动选择陌生项或越过前置阶段生成完整架构。可交预备清单并说明等待选择。用户说“都不会”即选当前清单；按阻碍当前目标的程度排序，清单很长时聚焦首批并说明余项待学，不默认一次生成几十个教程。

## B. 每项陌生技术做一个完整最小 Demo

1. **确定认知目标**：一句话写明要理解什么，如“调用者只知道契约和地址，另一个进程执行并返回对象”。取一个最小动作与安全合成数据，不依赖企业账号、数据库或真实接口；不要拿项目完整业务充当 Demo。
2. **核对版本/API**：优先匹配目标应用的可见版本/运行时，按必要公开库名和版本查询官方资料。版本未知时明确选定教学版本与理由，不冒充项目安装版；私有包不上传外查。不能核对时标未核对并收窄到概念示意，不能承诺可运行。
3. **构造最小实现**：先给带职责的文件树，再按树的顺序给每个文件完整内容。每个文件为何存在、数据谁提供/谁接收、关键 API 参数与返回/回调意义一起解释。一个概念一条链，不默认加认证、数据库、Docker、测试框架或重型构建。
4. **集中讲流程**：在同一文档给时序图/文字流、真实示例输入、每步处理、返回对象和预期终端/页面结果；至少解释一个常见失败及停止/清理方式。时序图优先清晰，无需强制手绘。几行骨架/伪代码必须明确标为示意，不当作最小可运行实现。
5. **写操作说明**：运行时、精确依赖版本、安装/启动目录、终端顺序、命令、预期结果都齐全。提供命令不等于执行。默认生成完整文档；用户要求“创建源码/落地/运行”才在该 Demo 子目录创建对应文件，不能修改业务包、根清单、锁文件、workspace或CI。执行安装/服务监听按已有授权；无授权先交完整材料再请求具体执行授权。
6. **映射回项目**：用一小表对照 Demo 的契约、创建/注册、调用、消费者与实际项目文件/符号/封装。实读不够写待确认及下一位置，不编造路径；自定义 Wrapper/内部包说明封装角色与可见 export/import，底层机制留给 library/deep。共享包学习可用本地两个目录的 export/import 或匹配包管理器的两包示例，不能把多包构建误演示成 RPC。
7. **交付与接续**：用 [技术 Demo 模板](../../assets/templates/tech-demo.md) 保存；格式校准看 [完整正反例](../examples/technology-demo.md)。明确“文档已生成”“Demo 已运行验证/未运行”“用户表示理解”三种状态，互不代替。

适配遵循目标运行环境：React 演示必要 Provider/组件/Hook；Vue 演示 app.use/provide/composable；React Native 使用匹配平台的组件与启动前提；Unity 说明场景/组件挂载、编辑器版本与观察结果。模拟器/Unity不可用时如实未运行，不为了方便把移动/游戏技术改成浏览器 Demo。

## C. 返回原分析，不重开扫描

结束给唯一入口 `技术栈demo/README.md`（仅一项也可直接链接其文档）、本轮完成项/待学项和原任务续接点。默认提示“看完后回复继续，或指出 Demo 哪一步不明白”；不自称用户已经掌握，不强制答题。用户确认继续/跳过才恢复原任务；此前已明确要求“生成后自动继续”的按该授权执行，不反复问。剩余已选陌生项未完成时保留待学，不冒称全部完成。

上下文至少保留：原目标、应用、版本、当前节点、用户明确熟悉/陌生/跳过项、已交付 Demo 与下一位置。用会话或请求保存的个人记录即可，不增加 JSON 状态机。恢复后按原 workflow 建立全貌/职责、入口结构和业务链；Demo 文档不重复粘贴到主指南。

- 每项选择的 Demo 有完整实现、操作、示例数据、预期结果和项目对应位置/待确认项。
- 文件集中、版本和验证状态真实，保存及执行边界清楚。
- 原任务有续接点；前置学习完成不等于项目分析已完成。
