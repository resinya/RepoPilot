# Teach：一步练习与反馈

## 输入、职责、产出

输入：用户学习目标、当前节点、已有背景和实际掌握依据。默认会话，保存练习按[outputs](../contracts/outputs.md)。用户请求学习给方向与提示；明确请求实施才修改。涉及框架样板文件、配置或依赖注入模块时，先按[讲解契约](../contracts/explanation.md)做骨架优先拆解与配置字段枚举。涉及用户可能不熟悉的技术栈，先列技术栈并询问，简报后再带教。

## 步骤

0. **前置简报**：若目标节点用到用户可能不熟悉的技术栈，先按[讲解契约](../contracts/explanation.md)列出技术栈并询问；对其做白话概念→本项目用法→常用API→关系→流程图的简报，完成再进入观察。完成：读者有前置认知，不盲目前进；简报到 library 深度转[library](library.md)。
1. **观察**：读一个目标相关节点，指出真实位置、职责与上下游；用骨架优先方式先给最小框架结构再标业务叠加。完成：练习材料来自项目，不是通用demo。
2. **理解**：用白话解释输入/输出与约束，讲清时先给最小骨架再叠业务、分清框架默认与项目新增；可给一个理解问题且可跳过。完成：不将测验作为继续看代码门槛。
3. **练习**：给一个小任务，文件/效果/步骤/完成条件/验证前提齐全。完成：能在有限改动中检验一个认知点。
4. **反馈**：根据用户回答/实际代码/运行证据指出差异与下一练习。完成：已展示、确认理解、用户报告、实际验证分开记。
5. **记录**：请求保存才写local/learning并复核进度。完成：个人记录不进入共享概览或Skill。

例：CLI识别空参数为何错误→解释退出码→参照同类测试设计一个空白输入检查；服务端可围绕参数校验→错误转换，客户端围绕生命周期→清理。练习不自动授权安装/运行。
