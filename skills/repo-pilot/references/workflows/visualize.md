# Visualize：一个案例，完整时序，集中展示数据

## 目标与边界

用于“用图说明模块和数据变化”“不要大段代码”“可点击地图”。默认一页整合模块、完整场景和数据变化，核心内容直接可读；目录导航和展开证据只是辅助。只有用户明确要求逐层钻取才用钻取布局。默认一个本地自包含 HTML；仅要静态图时按[图示契约](../contracts/diagrams.md)用文字树或 Mermaid。任务交付不是启动目标应用、发布网站或模拟真实业务请求。

优先复用当前 business/trace 证据，只补关键缺口。现有项目可视化则修改现有成果，不覆盖用户内容。模板见[离线业务地图](../../assets/templates/business-map.html)；模板中的订单内容全是合成演示，必须替换成当前实读事实。

## 八步 SOP

| 阶段 | 怎么做 | 阶段结果与完成条件 |
| --- | --- | --- |
| 1 范围 | 明确应用、业务、当前实现和读者目标；复用历史 | 主线和其他版本/协议分开；仅重大歧义才问 |
| 2 证据 | 注册→触发入口→处理→存储/外部调用→输出消费者 | 每个关键节点、每一跳有来源，缺实现标断点 |
| 3 结构 | 系统/应用→职责模块→业务步骤；按职责分组 | 同页看到层级和职责；结构关系不冒充执行顺序 |
| 4 节点 | 按下方内容约定提炼 | 业务职责优先，文件职责作为可展开证据；不展示整段源码 |
| 5 数据流 | 先定一个案例与固定参与者，把交互按较大业务阶段归组 | 时序图能明确谁传给谁；请求、内部对象、状态及响应有模拟结构和字段来源 |
| 6 呈现 | 同页完整时序图＋所有业务阶段的案例与数据，模块职责作辅助 | 不是每个函数一页；核心无需点击展开；导航仅定位/高亮，其他阶段仍可读 |
| 7 检查 | 内容复核＋脚本语法＋实际浏览器交互（工具可用时） | 未测与已测分开；无工具不称点击/视觉验收通过 |
| 8 交付 | 保存一个页面，按需索引主文 | 给入口、读法、覆盖和未确认项；不另生多份重复说明 |

## 节点与步骤内容

内容用模板中的内嵌数据对象维护；它只是页面内容，不增设 JSON Schema、后台或 Agent 调度器。

**节点**：稳定 id、业务名称、职责、子节点 id、输入字段/含义/来源、处理与分支、输出字段/含义/消费者、负责文件/符号及作用、证据状态与未知。子节点表示包含关系，不能靠排版赋予调用顺序。一个节点可在多个父节点中出现，返回按实际进入路径处理，结构循环停止钻取并注明关系。

只纳入当前认知目标需要的核心职责，不把全仓目录都展开。先用有限模块建立全貌，再把当前场景的完整数据链集中在下方；重复公共能力只保留职责摘要，不反复复制内部流程。

**场景步骤**：业务名称、发送方/当前处理方、接收方/下一边界、关系类型（HTTP/内部调用/消息/存储/重定向/本地状态等）、实际路由或入口、处理前字段、转换/校验/状态变化、处理后字段、一句话变化、来源与断点。输入输出表必须有含义，不只写 `data`、`response`。

## 案例与时序的呈现 SOP

1. **给一个连续故事**：谁做了什么、目标是什么、涉及哪个应用/模式。可以模拟，但人名、ID、域名、令牌和配置假设标清；同一组例值贯穿，不能每段换人/换ID。
2. **固定参与者**：浏览器、网关、外部平台、存储、业务服务等来自当前实读关系。职责写在泳道标题下；内部模块与网络进程标清，不靠“发送方/当前处理方”混称来解释。
3. **画完整时序**：每条箭头是明确方向的消息/调用/返回，有编号和关系类型。重定向拆清“网关→浏览器的302”和“浏览器→外部平台的请求”，不能画成网关直接替用户登录。
4. **按业务阶段讲**：通常3～5个足够，复杂场景按真实目标调整。一次读取配置、查Redis、生成参数可在“发起并跳转”内一起解释，不为每个技术动作创建细页。
5. **就近展示数据案例**：关键消息直接给URL/query、headers/body、JSON对象或事件样子；同处给字段含义与来源、处理后结果。细项已包含在阶段内，别再重复三组输入/处理/输出弹窗。
6. **区分谁发送与数据来源**：网关发给浏览器的授权地址里，client_id可能来自管理员保存的配置，state由网关生成；它们不是浏览器这次传来的字段。来源分为路径/query/body/header、配置、存储、上一步结果和本步生成，未知不猜。
7. **保持语义准确**：模拟请求值不是运行记录；内部参数、存储记录和响应摘录不能都叫API响应JSON。多个调用合并讲时标“结构汇总”，依赖真实顺序；条件、失败和缺实现留在相关阶段。
8. **交互只帮助跟读**：阶段导航/上一阶段/下一阶段只滚动或高亮，完整时序与其他阶段仍在本页。当前模块职责和负责位置一起给，代码/长证据按需收起。

模板的场景steps表示较大业务阶段，每阶段messages记录from/to、label、kind、entry、shape、fields（name/meaning/source）、result和evidence。shape允许字符串或对象，必须标模拟/实读/汇总的类型。普通节点仍按职责组织；旧字段没有细分来源时如实显示未记录，不自动补造。轻量消息可用一句案例说明；关键数据样子直接可见。

**字段契约（与模板渲染逻辑一致，改动前先读 `assets/templates/business-map.html` 的脚本）**

| 位置 | 字段 | 行为 |
| --- | --- | --- |
| 顶层 | title / scope / status / root | Hero 三行与模块区起点；场景有 title 时覆盖页面标题 |
| 顶层 | participants[{id,name,role}] | 时序图泳道；role 超过 15 个汉字会被截断，必须写短 |
| 顶层 | sources[] | 来源与验证范围；必须含模拟值声明、未核验项、不混的并行实现 |
| scenario | story / legacyStages[] | 一次连续模拟案例与开关假设；legacyStages 长度须等于旧细步数，用于折算旧 hash |
| step | name / summary / processing[] / result / boundary | 大阶段标题、概括、动作列表、阶段结果与边界；阶段数控制在 3～5 |
| message | from / to / kind / entry | 泳道 id、关系徽章与实际入口；id 未命中会显示“参与者未定义” |
| message | shape / fields[{name,meaning,source}] | 代码块与字段三元组；source 未知写未记录，不猜 |
| message | case | `false` = 轻量卡（只留编号/方向/label/entry/result）；省略或 true = 完整卡 |

编号在全部阶段内连续递增，时序图箭头与下方卡片共用同一个计数器，必须一一对应。关键数据卡通常占全部消息的 40%～60%：全压成轻量卡会退回概念图，全展开会淹掉主线。URL 状态为 `#scenario=<id>&section=step-<n>`，旧 `flow`/`step` 仍识别。

不把内部方法画成 HTTP 请求；不知道部署前缀时保留变量；外部身份令牌、本地凭证和临时会话各有自己的角色；实体声明不证明持久化成功。

## 页面行为与风格

- 同一个场景所需信息在一个页面直接展示，先案例与完整时序，再按大阶段说明数据；内部目录只作定位，不通过多个页面和弹窗拼答案。
- 模块结构与执行数据流分区展示；默认完整呈现当前场景所有步骤，多协议只在切换场景时改变流程。
- 职责、字段含义、转换/条件和关键未知直接可读；长源码、长API表与补充证据才收起。文件的业务作用写在正文，实际位置可展开核对。
- 用户明确要钻取时才增加节点点击、面包屑、返回和步骤选择；保留本页完整摘要，不以交互代替解释。
- 本地离线内容，不读取真实接口、环境、浏览器认证缓存或账户数据；不自动打开目标服务。
- 文本通过安全的 DOM 文本节点插入，URL 状态要校验；避免把源码文本直接拼成 HTML 或可执行 JS。
- 若用模板内 JSON，安全序列化 `<`（例如替换为 `\u003c`），防止 `</script>` 提前结束；不把私有绝对路径和身份值写入通用模板。
- 用户给参考图时按参考图；没有参考时清晰平面即可。可用深色背景、蓝色模块、灰色连线，不强制品牌或手绘；时序优先清晰。已认可视觉后不继续扩张特效。
- 无需增加构建/框架依赖；确实需要其他呈现形式时遵从用户目标。宿主只支持内联片段时用其形式，不硬称可离线 HTML 已导出。

## 验收

内容检查：结构层级、数据来源、转换/条件/失败、版本边界和每跳证据可核对；未知在步骤内可见。页面检查：不点按钮就能读完主场景，目录跳转、证据展开、场景切换、刷新、键盘和小屏；启用钻取才测面包屑与返回。脚本错误与空流程降级有记录。页面交互通过不等于真实业务运行通过。

正反例见[交互地图示例](../examples/interactive-map.md)。只交截图、无字段含义的箭头、无法返回的模块堆叠或十份分散说明，均不达到该任务目标。
