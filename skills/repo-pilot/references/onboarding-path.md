# 上手路径协议

当使用者的目标是「跑起来」或「带新人熟悉项目」时使用本文件。交付物是**可执行动作序列**，不是描述性说明。

## 环境准备段

按依赖清单逐项列出，命令必须可直接复制执行，并标注包管理器：

```bash
# Node 生态（pnpm 与仓库 lockfile 一致时用 pnpm，勿混用）
pnpm install
pnpm dev
```

必须同时给出 Windows 与 Linux 的差异项：

| 事项 | Windows | Linux / macOS |
| --- | --- | --- |
| 终端 | PowerShell 或 Git Bash，CMD 不支持多数项目脚本 | bash / zsh |
| 路径分隔符 | 配置文件一律写正斜杠 `/` | `/` |
| 内联环境变量 | CMD 不支持，需 `cross-env` 或 PowerShell 写法 | 原生支持 |
| 换行符 | `autocrlf` 开启时 `.sh` 脚本会报 `^M: bad interpreter` | 无此问题 |

## 配置段

从 `.env.example` 或配置样例出发，逐项说明：变量名、作用、留空时的兜底行为、是否必须。

不要罗列全部变量。只处理**启动必需**的那几项，其余指向配置文件本身。

## 验证段

给出一条能在 2 分钟内完成的验证动作，让使用者确认自己确实跑通了：

- 服务类：访问的 URL 与预期响应
- 脚本类：一条最小输入的运行命令与预期输出
- 库类：一个最小可运行的调用示例

## 新人路径段（仅当目标是带新人时）

按认知顺序而不是目录顺序组织，先跑通再理解：

1. 把项目跑起来，改一行文案看效果变化
2. 跟一条最核心的业务链路从入口走到数据落地
3. 在这条链路上做一个最小改动
4. 找到这条链路的测试并运行
5. 再展开其他模块

每一步都要给出对应的文件路径，让新人知道去哪里看。

## 收尾要求

列出「最容易卡住的三件事」——环境版本、缺失凭证、需要外部服务。这三件事通常是新人流失的全部原因。
