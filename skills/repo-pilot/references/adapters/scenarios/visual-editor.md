# Deep 子流程 — 限定机制，React编辑器定向读法

## 输入与证据记录

用户明确要求解释内部机制或使用deep时读取。library帮助使用一个包，deep证明一个具体动作的调用、数据变化与生命周期；默认上手不自动进入。

输入：问题、当前应用/框架版本、触发操作、能力入口与已知断点。先复核当前源码，不盲信旧笔记；关键歧义才问。
每跳记录：文件/符号/行号、调用者、输入来源、处理/条件、输出去向、状态写入、副作用与未读边界。复用既有定位，缺入口则在目标应用找，不先重扫全仓。

不要混用同名组件的两套实现；跟实际 import、别名、聚合出口。声明版本与锁文件精确版本分清；动态模块缓存不是静态依赖图的全部。

Vue/RN/Unity用各自结构规则定位，再核对参数、状态、回调、清理与外部边界；下面A/B/C是React编辑器详细路径，不强套其他框架。非React完整机制待真实场景验收。

## A 拖入物料与画布操作

1. 找实际源与目标：拖拽Hook/backend、排序上下文或自定义pointer包装分别定位。
2. 跟源 item/type 到目标 accept/drop/onDragEnd，记录输入结构、条件与取消。
3. 目标得到的 client/source/relative 坐标逐处跟进；缩放、偏移、滚动与容器坐标必须有函数证据，不能凭经验补公式。
4. 跟到创建/更新模型动作、默认字段、ID、父子层关系和状态写入；放置回调返回坐标不等于已经创建成功。
5. 跟状态消费者到画布显示、选择与保存边界；拖入创建与拖动已有对象分场景，不拼一条全部都发生的链。
6. 只在已读证据下讲吸附、多选、撤销/重做、尺寸约束、触摸支持。

完成：能用一次具体操作解释“事件→数据/坐标→模型动作→状态→展示”。未见创建动作就明确断在那里。

## B 图层/物料渲染

1. 从实际路由/页面下的画布组件开始，找图层数据来源、过滤/排序、树结构与映射。
2. 跟包装层传入 props/context/store，再到真正组件实例化处；包装层的名字不证明职责。
3. 若动态加载：跟组件标识/版本、注册表/加载器、缓存键与结果、失败/加载分支。缺远端物料源码只解释消费契约。
4. 找 data/configuration/size 等实际 props 来源，区分模型、外部数据、预览与编辑状态；不擅自发明字段。
5. 跟相关 memo/effect、订阅与清理，解释何种已读变化会更新显示；完整生命周期要有挂载/更新/卸载来源，不从函数名猜。
6. 预览、编辑、移动运行页可能不同实现，选目标模式一条链；模式不同处单列。

完成：能给出“模型/数据→映射/加载→包装→组件props→展示”的证据链，指出内部实现可见和不可见范围。要谈性能须有相关代码/测量，不凭用了memo就声称已优化。

## C 节点与变化传播

1. 找真实 nodes/edges、nodeTypes或注册映射，区分节点画布与大屏组件模型。
2. 跟 onNodesChange/onEdgesChange/onConnect 等实际入口，核对参数如何转换、写哪个store或调用服务。
3. 定位状态消费者、选择/配置联动与持久化；节点位置变化不等于业务执行。
4. 用户问业务执行才继续找触发器、执行器、依赖顺序/事件传播与结果更新；可视连线本身不是运行逻辑证明。
5. 分支、循环、异步、错误与撤销按具体场景读；没有处理循环的证据不能补出“拓扑排序”。

完成：一个明确节点动作的前后状态变化，以及画布显示/业务执行的边界。只看类型映射不能回答执行机制。

## 输出与停点

用输入→关键步骤→状态前后→结果描述机制，配真实位置。时序只画已确认相关参与者，标静态预期；从未看过的数据库/网关不能加进去。

未知要给下一条最有价值证据：哪个符号、调用者、资源/包源码或需要观察的运行事件。用户愿意运行验证时再处理前置条件与授权，首次不执行。
