# 服务端适配：启动、接口、业务与数据

## 顺序与完成条件

1. **确认入口**：清单/构建＋真实启动或服务注册。完成：语言、框架、运行入口有证据，目录名不当服务。
2. **接口边界**：全局前缀/路由、校验/权限、输入输出与错误转换。完成：一个目标接口可定位，路由声明不当可访问部署。
3. **业务与依赖**：服务/注入/模块/领域处理→数据访问或外部调用。完成：依赖方向和职责实读，不强制Service/Repository命名。
4. **状态/外部边界**：持久化、事务、缓存、消息/后台任务按场景补。完成：声明与实际处理分开，数据库变更未运行不确认。

| 已读证据 | 典型路线，不作硬性目录 |
| --- | --- |
| Nest核心依赖、NestFactory、模块注册 | bootstrap→模块/注入→Controller/DTO→Service→数据访问 |
| Spring构建、启动注解、扫描/路由 | 启动→配置→Controller→业务→Repository |
| Go go.mod、main、服务注册 | cmd/main→配置/路由→handler→业务→数据访问 |
| Python清单、ASGI/WSGI/工厂或任务入口 | 创建/注册→路由/依赖→处理→输出/数据 |
| 其他框架/无框架 | 启动/注册→真实调用→输入输出/状态 |

多个启动入口只确认运行候选；独立部署/微服务需要部署与通信证据。跨仓网关不可见保留断点，真实环境不读。非JS类型必须替换清单来源，不照抄前端步骤。

## 新人业务主线

先按 [business](../workflows/business.md)识别应用和用户目标，再选择一个接口/事件，而不是从启动文件一路讲遍所有公共配置。

- **启动包装**：main 可能只调用公共 Starter/工厂。追到真实创建应用和监听点，区分框架入口、项目公共包装、应用覆写；清单组装和对象注册不当已经开始监听。
- **模块地图**：模块登记说明能力如何接入、依赖如何提供；一次请求直接进入匹配处理器，不“执行一遍所有Module”。构造注入的实现与token需实际匹配。
- **请求切片**：输入来源（query/body/header/用户上下文）→校验/权限→参数整理→业务调用→数据访问/外部调用→输出对象/统一包装。实际Controller也可能做业务判断，按源码解释，不强套分层最佳实践。
- **数据意义**：DTO描述/校验输入，VO/serializer/interceptor可能改变输出，Repository/Entity说明访问与映射。只有真正读取/写入代码支撑当前场景，不能靠名称证明持久化完成。
- **身份边界**：多个登录协议、网关/插件和SaaS/私有实现分别确认。外部身份结果、临时会话、本地用户、应用登录凭证、下游身份上下文各有用途；认证不当业务授权。
- **接口并非能力名**：chat、agent、render 等只是线索；根据处理与结果消费者区分固定流程、检索、工具决策、配置生成与持久化。未读的跨服务实现停在发送契约。
- **工程命令**：脚本名dev可能运行文档站。读脚本内容/转发目标，说明工作目录、应用参数、平台与依赖前提；列出命令不等于执行。

大文件按符号读取，呈现遵从小问题节奏；用户跳过配置就回业务入口。集中页面复用这条链，逐跳讲数据变化，不复制企业代码进通用Skill。
