# 大型项目分析方法演练 — 将经验变成可复用规则

## 目的与边界

这份演练提炼一次大型 React 前端、多应用工作区、关联 Nest 后端的静态探索方法，使用抽象角色和示意符号，不携带企业路径、代码、环境与数据。它不是项目总结，也不是框架已经全面验收的证明。

只有判断卡住或需要校准输出时读取。实际任务必须重新核对目标源码。工作区组织方式与 Model/Wrapper 等代码模式是不同维度，不能相互代替。

## 跑通的分析链路

| 步骤 | 先找什么 | 如何思考与判断 | 得到什么，何时结束 |
| --- | --- | --- | --- |
| 1 认边界 | 根目录、Git、workspace与应用清单 | 父目录多个独立仓库不等于同一个工作区；主前端与账号服务分开 | 主应用与接口补充边界；不用扫描所有后端 |
| 2 认产品 | README、导航、主要页面/编辑器目录 | 从工作台、编辑器、蓝图、填报等职责解释应用，不从框架名解释产品 | 用户知道产品能力与代码分工 |
| 3 认工程 | 根/子应用scripts、任务过滤、env注入与规范 | dev/start名字可能不匹配；根调度不证明启动所有应用；新清单与旧README冲突要标 | 目录/命令/前提/规范来源；不运行来猜答案 |
| 4 选主线 | 主应用入口、典型导航、关键能力 | 主应用先讲；其余应用先给地图，避免同时钻进四套实现 | 3～5个阅读点及选择理由 |
| 5 找挂载 | HTML/构建插件→入口→真实render | 同仓应用React/Router代际可能不同；名字只是候选 | 可证明的挂载根和初始组件 |
| 6 看包裹 | 根return、提前返回、Provider创建 | 加载/权限/配置决定页面是否出现；兄弟节点保持兄弟 | 包裹树与前提，少讲回调内部 |
| 7 到页面 | Router定义→Layout插槽→典型页面 | 看实际版本API和lazy/re-export；同名页面按真实import | 导航到页面的连续地图 |
| 8 找能力 | 页面块→物料/画布/配置/渲染/节点入口 | 投放、移动改尺寸、动态渲染与连线可能用不同库/模块 | 能力→位置→核心包→大致方向；到此即可先交付 |
| 9 找需求 | 文案/路由→目标块→事件/数据 | 先定位改动面；查询描述不等于已经请求；写后更新也要找 | 一张“哪里改、照什么例子、如何验证”卡 |
| 10 补接口边界 | Hook/服务→传输包装→代理→相关Controller | 只有静态证据；前端不是必然Axios；账号服务不代表所有API | 足以联调的边界与未知，不默认深读ORM |
| 11 交付与继续 | 整体地图、规范、定位卡、阅读点 | 一份带目录的主文档，按需附录；机制问题另开限定分析 | 新人能复述产品、指出开发位置与下一步 |

## 关键发现如何固化为规则

| 真实探索遇到的现象 | 不能得出的结论 | 应固化的规则 |
| --- | --- | --- |
| 根脚本过滤到 dev，但子包只声明 start | 这个命令能启动该应用 | 沿调度核对子任务名字，脚本文本≠运行验证 |
| 同仓不同 React/Router/query包代际 | 全仓都是一个现代版本 | 按应用记声明版本，按API选择读法 |
| 一个同名包从registry引入 | 改本地同名目录就生效 | 查workspace协议与import解析，标外部包边界 |
| 查询辅助函数返回描述/闭包 | 调用辅助函数就发网络请求 | 继续跟到查询执行器与传输层 |
| 函数名带AutoAbort，取消逻辑却被注释 | 请求自动取消已生效 | 名称仅线索，核对实际调用与可执行分支 |
| 编辑器含多个drag库 | 一个库负责所有拖拽 | 按投放/排序/尺寸/画布移动分别定位 |
| 动态模块加载后创建组件实例 | import索引包含全部物料依赖 | 明确动态加载边界；先给加载入口，再按需分析生命周期 |
| 页面叫移动管理 | 它就是手机消费页 | 独立核对终端入口、布局、输入和构建目标 |
| 前端与Nest路径静态匹配 | 服务可达、权限和DB已验证 | 区分静态路径证据、生产映射和运行行为 |

## 主 Skill 应怎样解释可视化平台

可用表达：“这个产品的主线是选择内容、编辑画布、调整属性、预览/发布。物料投放在源/目标组件；移动与尺寸由画布包装处理；展示入口把图层配置与数据交给对应组件；节点图在另一个模块维护。下面分别给实际文件、关联包和一个需求定位例子。”

这足以回答整体认知；接着找真实位置，不停留在这段抽象话。
不默认逐个讲坐标换算、完整生命周期或节点传播。用户明确问机制，再把问题、能力入口、关键符号和断点交给内部deep子流程。

## 怎样检验扩展框架没有复制错

Vue 用创建/插件、template、RouterView/slot 替换 React挂载/return；React Native 用注册、导航和Screen；Unity用场景、对象、组件与UI。共同保留“产品→边界→结构→能力→规范→需求”的问题顺序，而非强制所有框架都长成React。

正确产出必须有实读证据。若现在只有规则与官方约定，标“规则已提供，真实项目待验收”；不能拿这个React案例为其他终端背书。
