# 输出契约：一个认知问题在一个地方读完

流程定义分析动作，模板组织内容。本契约统一阅读顺序、文件命名和来源，阶段数量不决定文件数量。

## 1. 默认展示与整体顺序

项目分析默认在会话中给完整结果；用户要求生成、保存或可视化时才落盘。指定目录优先，否则目标项目 `.repopilot/`；先读已有资料。只解释局部模块无需先生成全仓报告。技术预备阶段先交相关技术/包关系表与熟悉度问题；答复或明确跳过后才按下列顺序生成整体指南。Demo 的默认保存是下节明确例外。

上手按以下顺序组织：
1. 一句话产品用途和本次范围。
2. 业务分工：应用/模块、用户目标、职责和入口。
3. 架构与核心技术职责：工程/运行/代码/数据，版本来源。
4. 一个代表场景：触发→参与者→输入/处理/输出→结果或断点。
5. 重要位置、项目规范与开发需求起点。
6. 3～5 步阅读路线，文件/符号、读后答案及下一步。
7. 影响当前理解的未知、来源和实际覆盖。

第一屏先给结论与阅读导航，后面在同一回复/文档展开。不设置 80 行或固定字数上限把一个问题拆到其他文件；也不默认罗列全量依赖、API 手册、每段实现。

## 2. 保存时默认一份主文

```text
<知识目录>/
├── 00-start-here.md         # 完整项目指南＋内部目录；唯一阅读入口
└── ...                     # 用户需要的专题/页面才增加
```

00 整合用途、业务模块、架构、技术栈、典型链路、工程规范与需求定位。用内部目录和锚点定位，不要求用户来回打开文件。阶段、目录、技术名都不是拆分理由。

只有明确要独立专题、全量附录、个人记录或交互成果时才创建相应位置：

| 任务 | 实际保存位置 | 内容/模板 |
| --- | --- | --- |
| onboard | 00-start-here.md | [完整上手指南](../../assets/templates/overview.md) |
| map / architecture / stack / business / standards | 更新00相应章节；明确要独立专题时用 guides/<主题>.md | [地图](../../assets/templates/map.md)、[架构](../../assets/templates/architecture.md)、[技术栈](../../assets/templates/tech-stack.md)、[开发](../../assets/templates/development.md) |
| locate | 00中当前需求卡，或明确独立的 changes/<需求>.md | [需求定位](../../assets/templates/change-card.md) |
| library | guides/libraries/<安全包名>.md；局部问答可直接更新原章节 | [单库](../../assets/templates/library-guide.md) |
| trace | 原业务章节；独立请求才 traces/<场景>.md | [数据链路](../../assets/templates/trace.md) |
| deep | mechanisms/<机制>.md，仅用户请求深入/保存时 | [机制](../../assets/templates/mechanism-report.md) |
| visualize | maps/<主题>/index.html | [单页业务地图](../../assets/templates/business-map.html) |
| walkthrough / teach | 会话；请求记录才 local/progress.md或learning.md | [个人记录](../../assets/templates/learning-record.md)、[练习](../../assets/templates/learning.md) |
| refresh | 更新原章节/页面与00复核区 | [复核](../../assets/templates/refresh.md) |

专题有主文时仅链接实际主文；只有一个独立专题/HTML 时可直接作为该任务入口，不强制另外建00索引。页面内也要有范围、来源和未知，无需重复一份长 MD。有00时新增一条语义链接即可，不重复页面全文。

已有01/02或其他历史资料，先保留链接与手写笔记；用户要求重组时才按[知识管理](knowledge.md)整合，不无授权删除历史。允许合理多文件，禁止把一条连续业务链按每个模块拆开。

## 3. 技术预备：独立目录，一项一份完整文档

[demo](../workflows/demo.md) 的熟悉度问题须告知默认保存位置。用户选出陌生项即按该学习流程生成；用户只在会话展示、不保存或指定其他目录优先。

```text
<目标项目根>/技术栈demo/
├── README.md                 # 标题“技术栈的使用”；技术清单、阅读顺序和原任务续接点
├── <安全技术名>/
│   └── README.md             # 一份完整文档：概念、树、所有代码、流程、运行、API、项目对应
└── <另一技术>/README.md
```

顶层 README 只导航与共用说明，不重复各项完整代码。一项技术不再拆 concepts/api/steps 等多个 Markdown；源码默认在文档代码块里，用户要求落地才创建树中的文件。不能把标题“可运行”用于缺代码或缺运行前提的示意。

不为此强制建立 `.repopilot/00-start-here.md`；已有主文则加一条相对链接即可。用户熟悉度/答题表现留会话或请求保存的个人记录，技术文档不写“某某不会”。命名、越界与笔记保护沿用本契约和知识管理；不覆盖同名用户内容。索引与技术文档记录版本/范围/来源，实际运行与预期结果分开。

使用 [Demo模板](../../assets/templates/tech-demo.md)；保存目录属于目标项目，不写安装 Skill 或 RepoPilot 工具仓库。此目录按技术选择拆分是用户需求，业务链仍集中在一份项目主文/页面中。

## 4. 阅读与证据标记

可用 ★ 必读 / ◆ 当前任务相关 / ○ 查阅，不必每段重复。证据分为已确认（静态）、推断、未知、已运行验证。技术重要性按启动、主要业务或当前需求说明原因，不按下载量或引用次数直接评分。

代表场景逐跳讲数据含义；结构图与执行流分开。关键未知留在对应步骤旁，不能只藏在文末免责声明。

用户要看数据传递时以一个连续案例和完整时序图组织，技术细跳按较大业务阶段归组。关键URL/请求头/对象形状直接给示例，字段来源和发送方分清；阶段导航只定位，不隐藏其他核心内容，不默认一函数一页。

## 5. 来源与更新

00来源区或独立专题/页面记录：Skill名称/版本、任务/目标、仓库/应用、实际日期、可得revision/工作区、静态或具体运行验证、已读/排除范围、本次生成/重组历史/来源未记录、实际新增/更新与未复核范围。

合成例须明确；重组日期不等于源码重新核验日期；旧来源不明不补造调用。共享事实、个人进度、Skill资源分开，默认无需 JSON manifest。

安全文件名去分隔符、..、控制字符、盘符和保留名称；文件名标题保留原业务/包名，冲突用稳定后缀。写入边界按[知识管理](knowledge.md)。

## 6. 交付检查

用户能在同一处理解当前问题；正文自足，链接用于证据/扩展。核对重要位置、实际状态、来源、唯一事实位置、有效链接和用户笔记。最后给关键成果、唯一打开位置和未确认项；未保存明确说未保存，未导出图片不称已有图片。
