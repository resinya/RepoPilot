# 输出契约

文件命名、信息层级、来源和更新的唯一约定。workflow定义动作，template定义骨架，避免路径和标准分叉。

## 1. 第一屏

默认会话展示；用户要求生成/保存才落盘，使用指定位置，否则目标.repopilot/；多个目标每项目一个子目录，先读已有笔记。

上手按顺序：
1. 一句话产品与范围。
2. **★ 架构**：工程、运行、代码、数据四维，未知也明确。
3. **★ 核心技术栈**：按职责解释，按应用区分版本。
4. **★ 最重要三个位置**及作用，不足三个如实列。
5. **★ 开始路线**：3～5步、文件/符号、读后答案、下一位置。
6. **◆ 未确认项**与下一证据。
7. **○ 产物目录/来源**与详情链接。

00默认600～1200中文字、80行以内，无长API表/全量清单；这是目标，用户要求深入可扩展。01/02先摘要再详情。核心技术默认5～10项、不凑数量；全量索引仅用户要求时生成。

## 2. 标记

| 维度 | 标记 | 作用 |
| --- | --- | --- |
| 阅读 | ★ 必读 / ◆ 当前任务相关 / ○ 查阅 | 先看什么 |
| 证据 | 已确认（静态） / 推断 / 未知 / 已运行验证 | 结论范围 |
| 技术重要性 | 核心 / 重要 / 按需＋理由 | 启动/主要业务/当前任务作用 |

重要不等于已验证；不按下载量、清单排序、引用次数直接评分。不适用或未发现明确写，不补造数据库/UI/队列。

## 3. 保存结构与产物

```text
<知识目录>/
├── 00-start-here.md        # 唯一入口、首屏、目录与来源
├── 01-architecture.md      # 架构/职责/关系/典型路径
├── 02-tech-stack.md        # 核心技术、版本、用途、证据
├── guides/                # 按需开发规范及libraries/
├── maps/                  # 按需独立地图，已有01则更新01
├── changes/               # 按需需求定位卡
├── traces/                # 按需业务链路
├── mechanisms/            # 按需内部机制
├── appendices/            # 按需全量索引或原始证据
├── diagrams/              # 按需图源和实际导出图
└── local/                 # 个人位置/练习，非共享
```

## 4. 元数据与来源

00来源区（单文件同处）记录产物类型、Skill名称/版本、任务/目标、仓库/应用标识、实际日期、可得revision/工作区状态、静态或具体运行验证方式、已读/排除范围，以及来源：本次按Skill生成 / 重组历史材料 / 来源未记录。列新增/更新文件和未复核范围。

专题文档短头部注明任务、范围、日期/源码状态、阅读级别，链接00来源区；单文件自己记录。不要给旧文档补造调用，重组日期不等于源码重验日期。默认无需JSON/manifest。

安全文件名去分隔符、..、控制字符、盘符和保留名称；冲突用稳定后缀，标题保留原包名。写入/迁移边界按[知识管理](knowledge.md)。

## 5. 检查和回复

核对第一屏、重要位置、步骤、状态、来源、唯一事实位置、链接和手写笔记。最后用短段落给关键结论、本次产物、唯一入口和未知；只展示说未保存。没有实际图片导出只交图源，不称PNG已生成。评分见[质量契约](quality.md)。
