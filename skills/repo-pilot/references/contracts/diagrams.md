# 图示契约

图用于减少理解成本，源码证据和交付路径仍按[evidence](evidence.md)与[outputs](outputs.md)。默认清晰文字树或小型Mermaid，不预设logo品牌、手绘或图片工具。

## 选择与步骤

| 问题 | 图形 |
| --- | --- |
| 应用/模块职责与边界 | 小型结构图 |
| 全局包装/页面结构 | 缩进树优先 |
| 数据/状态变换 | 聚焦流程图 |
| 请求/消息先后与条件 | 时序图，标静态预期 |
| 用户不清楚谁传数据、需要案例带读 | 固定参与者的完整时序图＋同号模拟数据案例，按大阶段归组；不一跳一页 |
| 需求哪里改 | 定位表通常足够 |
| 模块职责和逐步数据变化，需要集中阅读/导航 | [单页业务地图](../workflows/visualize.md)，核心直接展示，交互只作辅助 |

1. 定一个问题/范围；完成：不为画图扫描全仓。
2. 提取约5～9个关键节点，更多折叠；完成：每节点有实读角色/来源。
3. 边注明依赖/包装/调用/请求/状态等关系，未知虚线＋原因；完成：不同关系不混。
4. 节点短名、源码映射放图下；完成：图中文字可读、能定位。
5. 核对条件、兄弟关系、证据状态；完成：图不强于源码，时序不是抓包。
6. 交付可编辑图源；只有实际生成才附导出图片/路径。完成：没PNG不称有PNG。

用户明确品牌/手绘时才读[可选风格提示](../../assets/templates/diagram-prompt.md)。无工具保留Mermaid或文字；不安装渲染服务、不上传企业图到公共渲染站。图像服务仅在已有授权下发送必要内容。

## 内容与风格分开

同一份节点/边/条件/未知清单可以有多种表现，换风格时复用事实与图外位置映射。多图共用角色颜色、术语和图例，颜色不是唯一的区分方式。选择用途后再选风格：

| 用途 | 表现与约束 |
| --- | --- |
| 普通项目说明/维护文档 | 清晰平面、短标签、统一间距，先图源，少量颜色区分角色 |
| 用户指定 RepoPilot logo 风格 | 深蓝轮廓、青蓝水彩、纸白浅蓝底、克制地图导航元素；文字和关系优先 |
| 请求/回调时序 | 普通清晰技术风，参与者、消息、条件优先，不强制手绘 |
| 用户提供已有图要求重建 | 保留来源对象、布局、标签与连接，不顺手换架构或编缺失内容 |

提示词必须有“用途/读者→一个认知目标→精确标签与节点→关系/条件/未知→布局→风格→禁画内容→实际输出用途”，不能只写“高级手绘架构图”。具体可组合片段见可选风格提示。

图片产出后实际核对标签、方向、条件、断点和映射；修正再交付。没有看到实际渲染就说明未做视觉检查。图源、已渲染图、模型图片与原生可编辑对象分别表达，图片不是项目事实来源。

“图片放进 PPT”只能编辑图片位置，“可编辑 PPT”需要重建文字、节点与连接线。本 Skill 当前没有 PPT 转换工具；没有实际构建/渲染/核对就不能宣传对象编辑或转换完成。未来若扩展，须另有对象构建与实际成品验收，不能靠改扩展名实现。
